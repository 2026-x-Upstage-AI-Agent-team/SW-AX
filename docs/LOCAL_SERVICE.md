# 시상금 서류 검토실

이 안내서는 한글이 설치된 Windows PC에서 실행하는 **시연판**을 다룬다. 화면은 정적 HTML·CSS·JavaScript, API는 FastAPI, 저장소는 SQLite를 사용한다. 서비스를 시작한 뒤 브라우저에서 [업무 현황](http://127.0.0.1:8765/)을 연다. React와 Spring Boot로 구축할 운영판의 범위는 [운영판 전환 계획](IMPLEMENTATION_PLAN.md#운영판-전환)에 있다.

## 실행

아래 명령은 `service/`, `reporting/`, 시연 양식이 들어 있는 팀 작업 폴더에서 실행한다. 시연 PC에는 실행 환경이 설치돼 있다.

```powershell
.\.venv\Scripts\python.exe -m uvicorn service.app:app --host 127.0.0.1 --port 8765 --no-access-log
```

PowerShell 7에서는 `.\start-service.ps1`도 같은 주소를 사용한다. 같은 자료 폴더의 워커는 한 번만 시작된다. 새 PC에 구성할 때는 한글과 PowerShell 7을 설치하고 아래와 같이 Python 3.12 이상 가상환경을 준비한다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r service/requirements.txt
```

서버의 환경 변수 또는 프로젝트의 `.env.local`에 `UPSTAGE_API_KEY`와 `UPSTAGE_AGENT_ID`를 지정한다. 공식 두 팀의 검증에는 Studio 설정 버전 `23`을 사용했다. 다른 버전은 `UPSTAGE_CONFIG_ID`로 지정한다.

## 공식 자료를 접수하는 순서

1. 공식 ZIP을 푼 뒤 **서류 접수**에서 같은 대회의 HWP·HWPX를 함께 선택한다. 파일명이 같은 서류도 각각 접수된다. 00 지급내역서는 서비스의 출력 양식이다.
2. **접수·팀 배정**에서 신청서의 팀명·대표와 동의서 작성자를 확인한다. 신분증 사본 등의 소속이 불분명하면 **원본 대조**에서 원접수 경로를 확인해 팀과 근거를 저장한다. 한글 파일 접근 확인창이 표시되면 해당 원본 또는 생성 경로를 대조해 접근을 허용한다.
3. **팀별 서류 검토**에서 체크리스트의 쪽을 누르면 해당 원문이 열린다. Studio 판정과 담당자 결론은 따로 보관한다. 소속·금액을 대조한 뒤 지급정보와 결론을 저장한다. 보완본은 해당 팀의 **보완본 접수**에서 교체·제외할 이전 파일과 새 파일을 선택한다.
4. **지급내역서**에서 학생·대표 명단 초안, 팀 순서, 시상구분과 지원액을 확인한다. **지급내역서 생성 → PDF 미리보기 → 이 버전 확정** 후 HWPX와 PDF를 내려받는다. 한글에서 직접 수정한 HWPX를 같은 확정본에 다시 올리면 편집본의 PDF가 새 버전으로 생성된다.

보고서 제목은 접수 시 선택한 대회 공식 명칭이다. 신청서에서 추출한 프로그램명은 팀 검토 화면에서 대조한다. 지급액·세액은 담당자 입력값을 사용한다. 각 팀 지원액은 전체 학생 표에서 한 번만 합산한다.

## 메일과 저장 위치

외부 메일 계정 없이 검증하려면 실행 프로세스의 `MAIL_MODE`를 `local`로 설정한다. **발송 이력**에서 팀별 로컬 수신 본문을 열 수 있다. 로컬 메일함의 `.eml`은 자료 폴더의 `mail`에 저장된다. 외부 발송에는 담당자가 연결한 Gmail 계정과 팀별로 확인한 수신 주소를 사용한다. [담당자 Gmail 연결과 수신 확인](IMPLEMENTATION_PLAN.md#51-담당자-gmail-연결)

서비스 기본 자료 폴더는 `var`다. SQLite에 접수·배정·버전·판정·확정값·발송 이력을 보관한다. `files`에는 접수 원본과 검토용 PDF, `reports`에는 버전별 편철 파일이 있다. 이번 공식 두 팀의 시연 자료는 `var/acceptance`에 따로 보관했다.

## 재개와 검증

브라우저를 닫아도 서버가 실행 중이면 작업이 계속된다. 알려진 Job ID는 재시작 후 같은 ID로 조회한다. 생성 응답 유실로 **실행 이력 확인**이 표시되면 Studio에서 요청 시각과 파일을 대조해 기존 ID를 연결한다. 서류 변환 오류가 나면 한글 보안 확인창, 원본 파일의 암호와 손상 여부를 확인하고 접수 상세에서 판독을 재개한다.

회귀 시험은 별도 임시 DB와 모의 Studio 전송기를 사용한다. 기본 시험은 공식 set04 원본을 접수하고 파일 판독 경계에서 기록된 분류를 재현한다. 설치된 한글 변환과 실제 PDF 입력 구성까지 다시 시험하려면 같은 PowerShell 세션에서 `$env:AWARD_NATIVE_TESTS='1'`을 설정하고 파일 접근 확인에 응답한다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```
